### Состояние Wi-Fi функциональности

#### ✅ Рабочие компоненты
1. **mks_wifi.cpp** - полностью функциональный backend:
   - UART обмен с модулем ESP8266/ESP32
   - Парсинг бинарного протокола (A5...FC)
   - Построение пакетов команд
   - Обработка сетевых пакетов (NET status)
   - Обработка G-code пакетов (инъекция команд в очередь)
   - Обработка загрузки файлов

2. **menu_info.cpp** - статический экран статуса:
   - Структурированный вывод информации
   - Использование структуры MKS_WIFI_INFO
   - Форматирование IP адреса

#### ❌ Недостающие компоненты
1. **API层** для UI:
   - Нет публичных функций для запроса сканирования
   - Нет функционала для получения списка найденных сетей
   - Нет функций управления подключением

2. **Логика сканирования**:
   - Команда сканирования определена в mks_ui (0xA5, 0x07, 0x00, 0x00, 0xFC)
   - Парсинг результата (ESP_TYPE_WIFI_LIST) не реализован

3. **UI управления**:
   - Нет меню для ввода SSID/пароля
   - Нет меню для выбора сети из списка
   - Нет клавиатуры для ввода текста
   - Жесткая кодировка учетных данных в mks_wifi_settings.h

## ⚠️ Архитектурные риски

### 🔴 Высокие риски

#### 1. Протокольные несоответствия
- **Проблема:** Команды сканирования и подключения живут только в отключенном mks_ui
- **Следствие:** Неясна полная спецификация протокола обмена
- **Решение:** 
  - Тщательный анализ wifi_module.cpp, mks_ui/draw_*.cpp
  - Достать только необходимые команды
  - Тестирование на реальном оборудовании
  
#### 2. Парсинг ESP_TYPE_WIFI_LIST
- **Проблема:** Формат пакета со списком сетей неопределен
- **Следствие:** Может отличаться между версиями модулей
- **Решение:**
  - Анализ draw_wifi_list.cpp (структура WIFI_LIST)
  - Экспериментальное тестирование
  - Возможно потребуется отладка через логирование пакетов

#### 3. Экранная клавиатура
- **Проблема:** TFT_COLOR_UI не имеет встроенной touch-keyboard
- **Следствие:** Нужна новая реализация, различается от LVGL
- **Решение:**
  - Либо простая реализация (4000-6000 строк кода)
  - Либо попытка адаптировать LVGL код (высокий риск)
  - Рекомендуется: вариант простой реализации

### 🟡 Средние риски

#### 1. Ограничение RAM
- **Проблема:** STM32F4 на MKS Robin Nano имеет ~192KB RAM
- **Следствие:** Буфер для 20-30 сетей требует ~1.5-2KB
- **Решение:** Компактное хранение, динамическое выделение памяти, тесты

#### 2. Конфликты логики обработки серийных пакетов
- **Проблема:** mks_wifi_parse_packet() может иметь специфичные особенности
- **Следствие:** Разные модули (ESP8266 vs ESP32) могут отличаться
- **Решение:** Модульная архитектура, флаги версий, логирование

#### 3. Синхронизация с существующим UI
- **Проблема:** menu_info_wifi() статичен, обновления в фоне
- **Следствие:** Race conditions при изменении mks_wifi_info
- **Решение:** Mutex / критические секции, flushes

### 🟢 Низкие риски

- ✅ Добавление пункта меню в существующую структуру
- ✅ Форматирование и отображение информации
- ✅ Интеграция с существующим API Marlin
